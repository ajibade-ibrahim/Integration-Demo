Data model

Twenty-eight tables in six groups. The sync spine (§1) is the connection machinery — seven tables hanging off Integration, plus the two scratch tables holding a connect that has not finished — together with the identity records it writes. The commercial records (§2) are what the catalog, agreement and billing functions write: products and prices, subscriptions with their lines, entitlements and discounts, invoices and payments. The identity layer (§3) is four tables scoped to User instead, because resolving one company across three connections is by definition not something any one Integration owns. §4–§6 cover uniqueness, the string-typed unions and JSON columns, and the connection status lifecycle.

Transcribed from prisma/schema.prisma and the const-union types in src/core/types/common.ts. Some columns are strings that are not really strings. Status, type and JSON columns are modelled as String and constrained in application code — a shape inherited from when the tests ran on SQLite, which has neither enum nor Json through Prisma. Everything now runs Postgres, so promoting them to native enum / jsonb is available but not yet done. See §5.

Connection lifecycle

A connection is configured before it exists and created only after its credential is proven. OAuth and API keys take different routes to that proof, then converge on the same finalize step: store the credential, mark the integration active, and seed its default mappings.

Role
Hold draft configuration, prove credentials, create connections and delete them safely.
Called by
Connect routes, the OAuth callback, the API-key submit route and the delete action.
Calls
Registries, token storage, mapping seeding, source-account capture and identity reassessment.
Key entry
finalizeConnection(), connectWithApiKey()

Key files

FileResponsibility
integrations/draft-store.ts Table-backed, expiring draft of provider + functions. Nothing is persisted as an integration until a credential succeeds.
integrations/connection.ts createIntegrationFromDraft() and finalizeConnection() — the shared post-credential path, including mapping seeding.
integrations/deletion.ts deleteIntegrationAndReassess(): revoke where possible, delete records and keys, rebuild shared accounts, audit the removal.
oauth/oauth-service.ts buildAuthorizationRequest, handleCallback, getValidToken, refreshToken, checkReauthorization, revokeTokens.
oauth/state-store.ts Single-use, expiring OAuth state keyed to a draft or integration.
oauth/crypto.ts AES-256-GCM encryption for stored credentials; no built-in default key.
credentials/api-key-service.ts connectDraftWithApiKey() and connectWithApiKey(): probe the key, then finalize.

How it fits

  • A draft is not a connection. Provider and function choices are held in an expiring table row. A rejected or abandoned attempt therefore leaves no integration for the user to delete.
  • OAuth starts with a state token. buildAuthorizationRequest() resolves scopes for the selected functions and records single-use state. The callback consumes that state, exchanges the code, and captures the source account.
  • An API key is proven before storage. connectDraftWithApiKey() probes the provider, treats a failure as “try again” rather than a partial connection, and never logs the key. The draft survives so the user can re-paste without re-picking.
  • Both routes converge. finalizeConnection() refuses unsupported function/provider pairs, creates the integration row when needed, stores the credential, marks it active and seeds default mappings.
  • Seeding is what makes a connection useful. A connected integration with no rules would sync nothing, so defaults are applied once and never overwrite saved edits.
  • Reconnecting preserves work. A new credential updates access without discarding mappings, synced records or resolved accounts.
  • Deletion is a reassessment, not just a delete. The deletion path retires only the deleted connection's identity keys, rebuilds shared accounts from surviving members, clears fields whose only source is gone, and reaps empty profiles.
  • The audit stores no customer values. A deletion or withdrawal records provider, label, time, counts and affected account ids only.

Rules worth knowing

  • Nothing is saved until the credential works. A canceled approval or a mistyped key leaves no half-built connection behind.
  • State is single-use and expiring. A callback without a state the platform issued is refused, and two simultaneous callbacks with the same state cannot both succeed.
  • Credentials are encrypted at rest. There is deliberately no development fallback key: a key that ships with the code is not protection.
  • Revocation is best effort. Deletion completes even if the provider cannot be reached; the failed revocation is logged so the key can be revoked by hand.
  • An API key belongs to the user's account. Deleting the integration removes our copy but does not invalidate the key at the provider.

Open this when…

  • Creating an integration leaves an unexpected row, or a rejected key leaves one.
  • The OAuth callback fails with an invalid or expired state.
  • A new integration syncs nothing because it has no mappings.
  • A reconnect is requested after adding a function that widens the scopes.
  • Deleting a connection leaves an account that should have been rebuilt or removed.

Providers

Each outside system gets one folder under providers/. A provider knows how to authenticate, page and interpret its own API; it holds no orchestration and no direct database access. The engine decides when to call it, and the shared HTTP client owns the failure policy every provider needs.

Role
Translate between one provider's API and the core's handler contract.
Called by
The sync engine, field discovery, OAuth service and API-key connect flow.
Calls
providers/http.ts for requests; provider APIs over the network.
Key entry
provider.ts and the per-function *-handler.ts files

Key files

FileResponsibility
http.ts Shared provider HTTP session and failure policy: 401 refresh once, 429 bounded inline retry, 5xx run-level retry, other fails the run.
defaults-registry.ts Suggested mappings keyed (function, provider), applied only when a connection has no saved rules.
connect-url.ts connectHrefFor() and draftConnectHrefFor(), choosing the OAuth route or the API-key page.
<provider>/provider.ts The ProviderDefinition: name, auth shape, endpoints, API base and tenant-scope hooks.
<provider>/api.ts HTTP calls, pagination and response shapes for that provider.
<provider>/discovery.ts The field list offered to the mapping editor, usually from the provider's own schema endpoint.
<provider>/defaults.ts Default rules for each function the provider supports.
<provider>/*-handler.ts One sync handler per function/provider pair, yielding raw records in the provider's shape.
<provider>/fixtures.ts Deliberately awkward sample records used to exercise the handlers.

How it fits

  • The provider definition is the plug. It declares the credential kind, endpoints, authorize/token hooks and external-id scope. The registry validates the hooks required by that shape at startup.
  • Two credential kinds, one contract. HubSpot, Salesforce and the Mock CRM use OAuth authorization-code. Metrifox, Stripe, Chargebee and Stigg use a static API key, each with a different header or auth scheme. The difference is absorbed by the provider definition, not by a branch in the sync loop.
  • Handlers yield, they do not write. A handler pages the provider and yields raw records plus a completeness signal. The engine maps and writes them; the handler never imports the database.
  • One HTTP policy is shared. http.ts refreshes on 401 and retries once, waits and retries the same request on 429 so pagination resumes at the same cursor, and treats 5xx as retryable at the run level. Everything else fails the run with what was already written kept.
  • Discovery is optional. A provider without a registered discoverer yields an empty list; the mapping editor falls back to free-text entry rather than failing.
  • Defaults are a starting point. They are seeded when a connection is authorized, so it can sync immediately. A saved rule set is never overwritten by defaults.
  • Connect URLs follow the credential kind. connectHrefFor() sends an API-key integration to its paste page and an OAuth integration to its start route. Draft links use a distinct shape so a draft id cannot be mistaken for an integration id.

Rules worth knowing

  • Adding a provider is extending, not rebuilding. A new folder plus registrations in bootstrap.ts; no route, UI or engine change as long as the credential kind already exists.
  • Interpretation belongs in the handler. A transform formats; a handler decides what an unknown enum, boolean or status means. That is where the unknown-value policy is visible and tested.
  • Provider folders are testable without a database. They have no Prisma imports, which is what lets the integration suite run them against mocked provider APIs.
  • Practice providers are opt-in. The Mock CRM and the in-app Metrifox fake are served over real HTTP so the real client code runs unchanged, but only when a deployment enables them.

Open this when…

  • You are adding a provider or a new function to an existing provider.
  • A sync fails on pagination, rate limiting, authentication or a 5xx.
  • The mapping editor's field suggestions are wrong or empty.
  • A reconnect sends the user to the wrong route.
  • A provider value lands with the wrong meaning rather than the wrong format.

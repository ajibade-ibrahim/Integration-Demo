Add a provider

A provider is a folder plus a few registrations. If the credential kind already exists, no route, page or engine branch changes: the sync loop reads the definition and the handler from the registries. This walkthrough adds a small API-key CRM that syncs Identity.

Template
providers/metrifox/ — API key, identity only
OAuth template
providers/mock/ — full OAuth, fixtures, no network
New files
provider.ts, identity-handler.ts, defaults.ts, optional discovery.ts
Registration
bootstrap.ts and defaults-registry.ts
Contract
types/registry.ts

First, decide the facts

DecisionWhy it cannot be deferred
Credential kind OAuth needs authorize/token hooks and env credentials. An API key needs a header, a paste page and a probe. The union is discriminated, so the compiler forces the choice.
externalIdScope global means an id names one record everywhere. tenant means it only makes sense inside one account, and then tenantScopeValue is required.
Functions Each function needs a handler and a default rule set. Identity is the smallest useful start: two objects, one handler.
Objects A handler may only claim objects its function owns. A catalog handler cannot declare customer.

For this walkthrough: provider acme, API key, tenant-scoped, Identity only, objects customer and contact.

Step 1: the definition

Create src/core/providers/acme/provider.ts. The probe is the important half: a rejected key must throw InvalidApiKeyError, and any other failure must remain an ordinary error so the UI can offer a retry.

import { InvalidApiKeyError } from "../../credentials/errors";
import type {
  ApiKeyProviderAuth,
  ProviderDefinition,
  ProviderMetadata,
} from "../../types/registry";

export const ACME_PROVIDER_NAME = "acme";
export const ACME_IDENTITY_SCOPES = ["customers:read", "contacts:read"] as const;

const acmeAuth: ApiKeyProviderAuth = {
  kind: "apiKey",
  header: "Authorization",

  instructions:
    "In Acme, open Settings → API and create a read-only key. Paste it below.",
  placeholder: "acme_live_…",

  validateKeyShape(key: string): string | undefined {
    if (key.trim() === "") return "Paste your Acme API key.";
    if (/\s/.test(key)) return "Paste just the key value.";
    return undefined;
  },

  async probeCredential(key: string): Promise<ProviderMetadata> {
    const response = await fetch("https://api.acme.example/v1/me", {
      headers: { Authorization: `Bearer ${key}` },
      signal: AbortSignal.timeout(15_000),
    });

    if (response.status === 401 || response.status === 403) {
      throw new InvalidApiKeyError("Acme rejected the key");
    }
    if (!response.ok) {
      // Status only — a body may echo the request.
      throw new Error(`Acme probe returned ${response.status}`);
    }

    const me = (await response.json()) as { workspaceId?: string };
    return me.workspaceId === undefined
      ? {}
      : { workspaceId: me.workspaceId };
  },
};

export const acmeProvider: ProviderDefinition = {
  name: ACME_PROVIDER_NAME,
  label: "Acme",
  description: "A CRM with companies and contacts.",
  auth: acmeAuth,
  externalIdScope: "tenant",
  tenantScopeValue: (metadata) => metadata["workspaceId"],
};

If tenantScopeValue returns undefined, resolution emits no self-key for that connection. That is the fail-closed behaviour: losing a join is recoverable; merging two tenants' company 12345 is not.

Step 2: the handler

Create src/core/providers/acme/identity-handler.ts. Use createProviderSession() so 401, 429 and 5xx behaviour is the same as every other provider. Do not import Prisma here.

import type { RawRecord, TargetObject } from "../../types/common";
import type {
  ExternalRefs,
  HandlerContext,
  SourcePage,
  SyncHandler,
} from "../../types/registry";
import { asString, createProviderSession } from "../http";

interface CompaniesPage {
  companies: RawRecord[];
  next?: string;
}

interface PeoplePage {
  people: RawRecord[];
  next?: string;
}

const SESSION = {
  authHeaders: (key: string): Record<string, string> => ({
    Authorization: `Bearer ${key}`,
  }),
  credentialNoun: "API key",
} as const;

export const acmeIdentityHandler: SyncHandler = {
  objects: ["customer", "contact"],

  async *fetchPages(ctx: HandlerContext): AsyncIterable<SourcePage> {
    const session = createProviderSession(ctx, "Acme", SESSION);

    let url: string | undefined = "https://api.acme.example/v1/companies";
    while (url !== undefined) {
      const body = (await session.getJson(url)) as CompaniesPage;
      yield { object: "customer", records: body.companies };
      url = body.next;
    }

    url = "https://api.acme.example/v1/people";
    while (url !== undefined) {
      const body = (await session.getJson(url)) as PeoplePage;
      yield { object: "contact", records: body.people };
      url = body.next;
    }
  },

  externalIdOf(record: RawRecord): string | undefined {
    return asString(record["id"]);
  },

  externalRefsOf(record: RawRecord, object: TargetObject): ExternalRefs {
    if (object !== "contact") return {};
    return { customer: asString(record["companyId"]) };
  },
};

Customers must be yielded before contacts, because the writer resolves a contact's link through the customer index. If a provider returns both shapes together, buffer the contacts and flush them after the last customer page — that is what Metrifox does.

Step 3: default mappings

Create src/core/providers/acme/defaults.ts. Every rule must validate against the object schema; a broken default fails the connect, not just the first sync. Seeds are applied only when the function has no rules.

import type { FieldMappingRule } from "../../types/mapping";

export const acmeIdentityDefaults: FieldMappingRule[] = [
  { sourceFieldPath: "name", targetObject: "customer", targetFieldPath: "name", transform: "none" },
  { sourceFieldPath: "website", targetObject: "customer", targetFieldPath: "domain", transform: "domainFromUrl" },
  { sourceFieldPath: "industry", targetObject: "customer", targetFieldPath: "industry", transform: "none" },
  { sourceFieldPath: "createdAt", targetObject: "customer", targetFieldPath: "createDate", transform: "dateOnly" },
  { sourceFieldPath: "name", targetObject: "contact", targetFieldPath: "name", transform: "none" },
  { sourceFieldPath: "email", targetObject: "contact", targetFieldPath: "email", transform: "lowercase" },
];

Register the set in providers/defaults-registry.ts:

import { acmeIdentityDefaults } from "./acme/defaults";
import { ACME_PROVIDER_NAME } from "./acme/provider";

const DEFAULTS = {
  // ...existing entries
  [`identity:${ACME_PROVIDER_NAME}`]: acmeIdentityDefaults,
};

Step 4: discovery (optional)

Field discovery is what fills the mapping editor's source dropdown. It is optional: without one, the editor falls back to free-text paths. If the provider has a schema endpoint, add discovery.ts returning DiscoveredFieldDef[] for each object; the result is cached for an hour. Metrifox uses a hybrid: static fields plus keys sampled from one live page.

Step 5: register

Add the provider import and registration to src/core/bootstrap.ts:

import {
  acmeProvider,
  ACME_IDENTITY_SCOPES,
  ACME_PROVIDER_NAME,
} from "./providers/acme/provider";
import { acmeIdentityHandler } from "./providers/acme/identity-handler";
import { acmeFieldDiscovery } from "./providers/acme/discovery";

// --- providers ---
registerProvider(acmeProvider);

Scopes are added to the existing Identity registration, not a new one. Find its scopesByProvider map and add the provider entry:

scopesByProvider: scopeMap([
  // ...existing providers
  [ACME_PROVIDER_NAME, ACME_IDENTITY_SCOPES],
]),

Then register the handler, and the discoverer if you built one:

registerSyncHandler(IDENTITY_FUNCTION, ACME_PROVIDER_NAME, acmeIdentityHandler);
registerFieldDiscovery(IDENTITY_FUNCTION, ACME_PROVIDER_NAME, acmeFieldDiscovery);

Do not register a second Identity function: one definition serves every provider, and scopesByProvider carries the per-provider scopes. Registering the same name twice throws.

Step 6: prove it

  • Capability. canSyncFunction("identity", "acme") must be true and supportedObjectsFor must return ["customer", "contact"].
  • Defaults. validateMappings("identity", …) must return no violations — the shipped-defaults test does this for every handler pair automatically.
  • Handler. Add an MSW-backed integration test that yields a customer page and a contact page, then asserts the contact's link resolves.
  • Sync. Add an end-to-end sync test if the provider has a non-obvious pagination or association rule.
  • Full suite. npm test runs typecheck and every test; npm run test:unit is the fast loop.

Useful existing tests to copy from:

  • tests/unit/capability-truth.test.ts — capability and object coverage.
  • tests/unit/provider-auth-kinds.test.ts — registration rules for both credential kinds.
  • tests/unit/provider-defaults.test.ts — every default set validates.
  • tests/integration/metrifox-handler.test.ts — an API-key handler over a mocked API.

If you are adding a function instead

A function is a purpose, not a provider. The change is wider because it reaches the record model:

  1. Add the target objects to object-schema.ts, including field kinds and any readOnly associations.
  2. Add the objects to FUNCTION_OBJECTS and the function to FUNCTION_WRITE_ORDER.
  3. Register the function with dataModels and scopesByProvider.
  4. Add a writer branch in writeRecordsForFunction(), parents before children.
  5. Add handlers per provider and default mappings per handler pair.
  6. Teach survivorship and the data model only if the new objects need it; Identity is the only function with cross-connection resolution today.

Gotchas

  • No Prisma in a provider folder. The folder talks HTTP and returns raw records; the engine writes. That separation is what keeps handler tests database-free.
  • Ids must be stable. A synthesized id built from a mutable field duplicates every record on the next sync. Metrifox's synthesized contact id is deliberately derived from stable parts.
  • SourcePage.complete is a promise. Set it only when the list is whole for every parent yielded in this run. An incomplete fan-out must fail instead; otherwise reconciliation deletes live rows.
  • Probe errors are a policy, not a message. InvalidApiKeyError means “the user must fix the key”; anything else means “try again”. Swapping them misleads the user.
  • Scopes cannot be empty. resolveScopes() throws on an empty list and the picker filters the provider out, even for an API-key provider that never transmits them.
  • Register the defaults. A handler with no seeded rules connects and then refuses to sync with “No field mappings configured”.
